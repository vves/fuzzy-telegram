Connect TakeLight to Logic Pro

Use Apple’s built-in Recording Light profile to send record-ready and recording status to your Hue lights.

TakeLight 1.1.0+ · Verified with Logic Pro 12.3.1 and two Hue lights, November 20, 2026.

PrepareConnect LogicTest the lightsTroubleshoot

1. Prepare TakeLight and Hue

Install TakeLight 1.1.0 or later on your Mac and launch it before opening your DAW. A Philips Hue Bridge and compatible lights must be on the same local network. Hue automation requires an active trial or Lifetime Hue Unlock.

In TakeLight, use Hue → Discovered Bridges to find your bridge, press its physical link button when prompted, then use Hue → Select Lights. If your trial has ended, choose Unlock TakeLight… first; use Restore Purchases for an existing purchase.

In updated builds, choose DAW Connection → Automatic, then launch Logic Pro. TakeLight should show Automatic — Logic Pro. Alternatively, choose the Logic Pro (Recording Light) manual override; use that option in builds without Automatic. Your preference is saved across restarts.

Logic mode creates TakeLight State Receiver only. A missing TakeLight Out port is expected in this mode. No custom control-surface script is needed.

2. Add Apple’s Recording Light profile

  1. Open Logic Pro → Control Surfaces → Setup.
  2. Choose New → Install…, find manufacturer (other) and model Recording Light, and click Add.
  3. Select the Recording Light device in the Setup window and enter the settings below.

Logic sends recording status out to TakeLight State Receiver. The Input Port is unused by this one-way integration.

Builds 37 and earlier name this destination TakeLight In. Use that name with those builds. After updating to a build with the new name, reselect TakeLight State Receiver if Logic does not reconnect automatically. MCU ports for other DAWs remain TakeLight In and TakeLight Out.

Leave New → Automatic Installation enabled if you use it for other controllers. TakeLight’s Logic mode does not announce or answer as Mackie Control.

If you previously added a Mackie Control or experimental TakeLight profile, remove that old TakeLight-related registration or route its output away from TakeLight State Receiver. Keep one Recording Light profile driving TakeLight; preserve your unrelated control surfaces.

3. Test arm, disarm, record, and stop

  1. Start stopped and disarmed. Your lights should show their normal lighting.
  2. Record-enable an audio track. The selected lights turn blue.
  3. Disarm the track. Normal lighting returns after a short settling delay.
  4. Arm the track again and start recording. After any count-in, the lights turn red.
  5. Stop recording. If the track remains armed, the lights return to blue.
  6. Disarm the track to return to normal lighting.

Also try pressing Record directly with one disarmed audio track. Once Logic starts recording, the lights should turn red. Logic may automatically disarm the track on stop, in which case normal lighting returns.

If the lights do not respond

  • No TakeLight State Receiver port: launch TakeLight, confirm Logic mode, then reopen Logic’s Setup window and reselect the port.
  • Hue menus are disabled: check trial/unlock access, then restore or unlock from TakeLight’s menu.
  • Blue while you expect red: wait through the count-in, confirm Logic is actually recording, and check that Data 1: Recording is 95.
  • Unexpected changes: check for an older Mackie/TakeLight registration using the same output, and run only one copy of TakeLight.
  • Moving to LUNA or another MCU DAW: choose Automatic and quit Logic before opening the other DAW. TakeLight switches protocols for you. If both are open, Logic takes priority. Manual overrides remain available for builds without Automatic or unrecognized DAWs.
